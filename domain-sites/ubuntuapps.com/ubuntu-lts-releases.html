Ubuntu LTS releases explained: support timelines and upgrades

Ubuntu releases a new version every six months, in April and October. Every two years, the April release is an LTS (long-term support) release with five years of standard security maintenance, extendable to ten years with Ubuntu Pro. Interim releases are supported for nine months.

Updated November 2, 2026 · By the UbuntuApps team

How Ubuntu version numbers work

Ubuntu versions are named by year and month: 24.04 was released in April 2024. Each also has an alliterative codename, such as Noble Numbat. Even-numbered years' April releases (22.04, 24.04, 26.04) are LTS releases. Everything else is an interim release.

Recent LTS releases and support windows

Standard support ends roughly five years after release and Expanded Security Maintenance (ESM) through Ubuntu Pro about ten years after release. Exact end dates are published on Canonical's Ubuntu lifecycle page, which is the authority if anything below changes.

Canonical also sells a Legacy add-on that can extend support for some older LTS releases beyond the ten-year window, aimed mainly at enterprises.

What "support" actually covers

  • Standard security maintenance: security fixes for packages in the main repository (the core system and Canonical-supported software) for five years.
  • Universe packages: community-maintained software in universe gets best-effort community updates. Ubuntu Pro's ESM extends security coverage to many universe packages as well.
  • Snaps and Flatpaks: updated by their publishers independently of your Ubuntu release, so a browser snap stays current even on an older LTS.
  • Hardware enablement (HWE): LTS point releases (like 24.04.1, 24.04.2) can bring newer kernels and graphics stacks to support recent hardware.

Ubuntu Pro in brief

Ubuntu Pro is Canonical's subscription service. It's free for personal use on a small number of machines and paid for businesses. It adds ESM (extending security updates to ten years and to more packages), Livepatch for rebootless kernel security fixes, and compliance tooling for regulated environments. You can attach it from Software & Updates or with the pro command:

sudo pro attach <your-token>
pro status

Which release should you run?

  • Most people: the newest LTS. It's stable, widely documented, and supported for years.
  • Brand-new hardware: the latest LTS point release, or an interim release if the LTS doesn't yet support your hardware well.
  • Want the newest GNOME and kernel features: interim releases, if you're comfortable upgrading every six to nine months.
  • Servers and business machines: an LTS, with Ubuntu Pro if you need longer coverage.

A common approach: wait for the first point release (the ".1" release, usually a few months after April) before moving an important machine to a new LTS. By then early bugs have been fixed, and the upgrade from the previous LTS is typically offered automatically.

How to upgrade safely

  1. Back up your files and, ideally, take a Timeshift snapshot. See our post-install checklist for backup tools.
  2. Fully update your current release: 
    sudo apt update && sudo apt full-upgrade
sudo reboot
  3. Disable or remove third-party PPAs that might conflict. The upgrader disables most of them automatically.
  4. Start the upgrade: open Software Updater and accept the offer, or run: 
    sudo do-release-upgrade
  5. Choose your upgrade policy. In Software & Updates > Updates, "Notify me of a new Ubuntu version" can be set to "For long-term support versions" or "For any new version".
  6. After upgrading, re-enable needed repositories, run sudo apt autoremove, and check that your important apps work.

On an LTS, do-release-upgrade offers the next LTS only once it's considered ready, which is usually after the first point release. Using sudo do-release-upgrade -d forces an earlier upgrade and isn't recommended for important machines.

Fresh install or upgrade?

In-place upgrades usually work well and keep your files and settings. A fresh install can be cleaner if you've added many PPAs or manual changes over the years, or if you're more than one LTS behind. If you choose a fresh install, back up your home folder, keep a list of installed apps (apt-mark showmanual and snap list help), and use our app guide to rebuild.

Frequently asked questions

How do I know which Ubuntu version I have?

Run lsb_release -a or cat /etc/os-release in a terminal, or open Settings and look under System > About.

Can I skip an LTS release when upgrading?

The standard upgrade path goes one LTS at a time, for example 22.04 to 24.04, then 24.04 to 26.04. To jump further, upgrade in steps or do a fresh install.

What happens when my release reaches end of standard support?

It stops receiving regular security updates for most packages. You can attach Ubuntu Pro for Expanded Security Maintenance or upgrade to a newer release. Running an unsupported release online isn't recommended.
