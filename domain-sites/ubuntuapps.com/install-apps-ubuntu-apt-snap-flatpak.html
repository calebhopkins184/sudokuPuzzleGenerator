How to install apps on Ubuntu: apt vs snap vs Flatpak vs .deb vs AppImage

Ubuntu supports five common ways to install software. Use apt for most system tools and libraries, snaps or App Center for convenient self-updating desktop apps, Flatpak if you want Flathub's catalog, a .deb from the developer when there's no repository package, and AppImage for portable apps.

Updated November 2, 2026 · By the UbuntuApps team

apt: Ubuntu's native package manager

apt installs .deb packages from Ubuntu's repositories, which are split into main and restricted (supported by Canonical) and universe and multiverse (community-maintained and restricted-license software). Packages in an LTS release are kept stable and receive security fixes, but usually don't jump to new major versions.

# Always refresh package lists first
sudo apt update

# Search and get details
apt search image editor
apt show gimp

# Install, upgrade everything, remove
sudo apt install gimp
sudo apt upgrade
sudo apt remove gimp
sudo apt autoremove      # clean up unused dependencies

# Enable the universe repository if a package isn't found
sudo add-apt-repository universe

Use apt for anything that integrates deeply with the system, such as drivers, command-line tools, programming languages, and servers.

snap: Canonical's universal packages

Snaps bundle an app with its dependencies, run with confinement (sandboxing), and update automatically. App Center, Ubuntu's built-in store since 23.10, is built around snaps, and some core apps such as Firefox ship as snaps by default.

snap find spotify
sudo snap install spotify
sudo snap install code --classic   # "classic" = less confinement, needed by some dev tools
snap list
sudo snap refresh                  # update now instead of waiting
sudo snap revert spotify           # roll back to the previous version
sudo snap remove spotify

Pros: same version across Ubuntu releases, automatic updates, easy rollback, and many apps published by their own developers. Cons: larger disk use, sometimes slower first launch, and occasional theming or file-access quirks from confinement. Check the publisher name on the store page; a green check or star means a verified publisher.

Flatpak and Flathub

Flatpak is another sandboxed, distribution-independent format. Its main repository, Flathub, has a large catalog of desktop apps, often with recent versions. Ubuntu doesn't include Flatpak by default, but it takes a minute to set up:

sudo apt install flatpak
# Optional: GNOME Software with Flatpak support (installs alongside App Center)
sudo apt install gnome-software-plugin-flatpak
# Add the Flathub repository
flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo

Log out and back in (or restart) so Flatpak apps appear in your menu. Then:

flatpak search kdenlive
flatpak install flathub org.kde.kdenlive
flatpak run org.kde.kdenlive
flatpak update
flatpak uninstall --unused     # remove leftover runtimes

Flathub marks apps published by their developers as verified. The Flatseal app lets you review and change each Flatpak's permissions.

.deb files from developers

Some vendors, such as Google (Chrome), Microsoft (VS Code), and Valve (Steam), publish official .deb packages on their websites. Install them with apt so dependencies are resolved automatically:

sudo apt install ./google-chrome-stable_current_amd64.deb

The ./ matters: it tells apt to use the local file. Many official .deb installers also add the vendor's repository so the app updates with sudo apt upgrade. Only install .deb files from sources you trust, because they run with administrator privileges during installation.

AppImage: portable single-file apps

An AppImage is one file that contains the app and its dependencies. Nothing is installed system-wide.

chmod +x Obsidian-x.y.z.AppImage
./Obsidian-x.y.z.AppImage

Many AppImages require the FUSE 2 library, which isn't installed by default on recent Ubuntu releases. On Ubuntu 22.04 install libfuse2; on 24.04 and later the package is libfuse2t64. Don't install the older fuse package, which can conflict with the system's FUSE 3. Since Ubuntu 24.04, AppArmor restrictions on unprivileged user namespaces can also stop some Electron-based AppImages from launching; check the app's documentation for the recommended fix.

AppImages don't add menu entries automatically. Tools such as Gear Lever (Flatpak) can integrate them into your app menu and manage updates.

PPAs: use sparingly

A Personal Package Archive (PPA) is a third-party apt repository hosted on Launchpad. Some projects, like OBS Studio, maintain official PPAs that provide newer versions than the Ubuntu archive.

sudo add-apt-repository ppa:obsproject/obs-studio
sudo apt update && sudo apt install obs-studio
# Remove a PPA later
sudo add-apt-repository --remove ppa:obsproject/obs-studio

Each PPA you add can replace system packages, so stick to official ones and keep the list short.

Which should you use?

  1. Is it a command-line tool, library, driver, or server? Use apt.
  2. Is it a desktop app in App Center from a verified publisher? The snap is the easy path.
  3. Want a newer version or an app only on Flathub? Use Flatpak.
  4. Vendor offers an official .deb with its own repository? That's a good choice for apps like Chrome and VS Code.
  5. Want to try something without installing, or carry it on a USB drive? AppImage.

Whatever you choose, prefer one format per app, and get packages from the developer or an official store rather than random download sites.

Frequently asked questions

Can I have both a snap and an apt version of the same app?

Yes, they install side by side, which can be confusing. You'll see two entries in your app menu. Remove the one you don't want with sudo snap remove or sudo apt remove.

Why does apt install a snap for Firefox?

Since Ubuntu 22.04, the firefox apt package is a transitional package that installs the Firefox snap. Mozilla also publishes its own apt repository if you prefer a .deb build.

Are PPAs safe?

A PPA is a third-party repository that can update any package on your system. Use PPAs only from projects you trust, such as an app's official developers, and remove them before major release upgrades if they cause problems.
